## 1. 项目背景与目标

### 1.1 背景
个人/家庭的数据越来越多地散落在手机、电脑、云盘和各种账号里。我们希望把数据**收回到自己掌控的私有设备**上,构建一个数据中枢,同时通过亲手从零构建来深入理解现代存储、网络与 Web 系统的原理。

### 1.2 项目定位
**PNAS(Personal NAS)** 是一个**纯从零自研**的私有化网络存储系统:

- 面向 **1 个家庭 / 小团队(2–8 人)**,多用户、有权限隔离;
- **纯软件设计,不绑定任何特定硬件**(先做软件,硬件选型后置);
- 以 **Web 端为核心入口**,局域网为主要使用环境,支持配置化地开放外网访问;
- 桌面设备(macOS/Windows)具备**自动上传/备份**通道;手机等其他设备经**响应式 Web 批量上传**访问(v1 不做原生 App,见决策 D10);
- 目标价值排序:**数据不丢(可靠性)> 数据安全(隐私)> 随时随地可取(可用性)> 好用(体验)**。

### 1.3 成功标准(试运行期验收指标,每条含可测口径、验证方式与需求追踪)

| # | 标准(可测口径) | 验证方式 | 追踪 |
|---|---|---|---|
| SC-1 | **多用户隔离**:两个普通成员账号互不可见对方私有数据 | 账号 A 经 API 与 UI 访问 B 的私有路径 → 403/空列表 | FR-AUTH-06、NFR-SEC-03 |
| SC-2 | **备份与照片入库**:桌面设备(macOS/Windows)关键目录按策略**自动**备份,连续 14 天每日成功、无重复副本;手机照片经 Web **批量上传**可入库 | Agent 任务日志连续 14 天 SUCCESS;抽查哈希去重;Web 上传 50 张照片 → 时间线可见 | FR-BACKUP-01/02、FR-FS-06、FR-MEDIA-07 |
| SC-3 | **时间线性能**:1000 张照片时间线首屏 ≤ 2 s | 局域网参考浏览器(Chrome,预热后)计时,记录口径 | FR-MEDIA-02/03、NFR-PERF-03 |
| SC-4 | **传输性能**:100 GB 级目录可稳定上传/下载,单流吞吐 ≥ 同一主机局域网基准(iperf3)的 80% | 部署时记录基准,验收时对比;全程无中断、校验一致 | FR-FS-02、NFR-PERF-01 |
| SC-5 | **误删可找回**:任一成员误删文件,可在回收站/版本历史经 **UI** 恢复,内容哈希一致 | 删除 → 回收站恢复(或回滚版本)→ 比对哈希 | FR-FS-03、FR-FS-04 |
| SC-6 | **整机恢复**:数据目录 + 元数据可恢复到一台新机器,RTO ≤ 半天 | M4 执行一次演练并产出报告 | FR-BACKUP-05/06、NFR-REL-05 |

> 说明:SC-4 用"相对基线"取代旧稿的绝对"千兆 80%",以兼容"暂不绑定硬件"的决策(D2);绝对数值留待部署后校准。

## 2. 用户与角色模型

| 角色 | 说明 | 权限示例 |
|---|---|---|
| **管理员(Admin)** | 系统所有者,1–2 人 | 全部功能;用户/组管理;系统设置;查看审计日志 |
| **成员(Member)** | 家庭/团队普通用户 | 使用自己的私有空间;访问被授予的共享空间;可被授权管理某个共享空间 |

> 设计原则:
> 1. **账号制 + 最小权限**。不允许匿名写入;一切文件访问先过鉴权;
> 2. **不提供"访客账号"角色**(v0.3 移除,旧稿角色存在但无对应功能):对外的只读分享一律通过**外链**(FR-AUTH-07,C 级)实现,避免承诺不存在的角色;
> 3. 用户**默认仅由管理员创建**(决策 D12);开放注册为可选开关,默认关闭。

## 3. 范围界定

### 3.1 范围内(v1 目标)
1. 账户与访问控制(多用户、组、目录级权限);
2. 文件存储与多端访问/自动上传:桌面设备(macOS/Windows)目录**自动**上传,其他设备经 Web **访问与批量上传**;镜像式同步客户端后置(M7);
3. 照片 / 视频媒体管理(入库、时间线、相册;照片来源 = 桌面自动 + Web 批量);
4. 影音流媒体(直放格式 M3 可用;转码服务进 v1、M5 交付);
5. 集中备份(Agent 支持 macOS + Windows;含出站备份与恢复演练);
6. 系统支撑(任务队列、审计、通知、健康监控);
7. 内网为主 + 可选安全外网访问。

### 3.2 范围外(v1 明确不做)
- ❌ 下载器 / PT / 网盘离线(用户未选择);
- ❌ 多节点分布式存储 / 集群(单机为中心,异地备份用"副本"而非集群);
- ❌ 原生手机 / 桌面 App、移动后台自动上传通道(手机经响应式 Web 批量上传,见决策 D10);
- ❌ 人脸/物体识别(v1 不承诺,后置评估);
- ❌ 与 Dropbox / 网盘协议兼容或迁移工具;
- ❌ 邮件 / 日历 / 笔记 / 通讯录等"全家桶"插件生态;
- ❌ 硬件 RAID 管理与底层文件系统自研(文件系统采用成熟底层,自研其上的存储语义);
- ❌ 系统内应用层 at-rest 加密(数据静态加密由部署层磁盘/卷加密承担,见决策 D11)。

## 4. 功能需求(编号 FR,带优先级)

> 优先级采用 **MoSCoW**:M = Must(必备,v1 缺它不可用);S = Should(应有,缺它不完整);C = Could(可以有,资源允许再做);W = Won't(v1 不做)。每行"说明/验收要点"即该需求的验收口径。

### 4.1 账户与访问控制 — FR-AUTH
| 编号 | 需求 | 优先级 | 说明/验收要点 |
|---|---|---|---|
| FR-AUTH-01 | 用户创建/登录/登出 | M | **默认仅管理员创建用户**;可选开放注册开关(默认关,受 FR-NET-04 约束);登录支持记住会话 |
| FR-AUTH-02 | 密码安全存储与策略 | M | Argon2id/bcrypt 等强哈希;拒绝弱密码(默认最小长度/复杂度可配) |
| FR-AUTH-03 | 登录失败保护与会话管理 | S | 连续失败锁定 + 退避;可查看/吊销已登录会话 |
| FR-AUTH-04 | 两步验证(TOTP) | C | 可选开启,尤其管理员 |
| FR-AUTH-05 | 用户/组管理界面 | M | 增删改查用户与组,成员与管理员角色切换 |
| FR-AUTH-06 | 目录级权限(ACL) | M | 私有/共享/只读/读写;支持组;子目录继承与覆盖规则明确;判定在服务端执行 |
| FR-AUTH-07 | 分享链接(只读外链) | C | 带密码/有效期/只读、可撤销;是**唯一的只读对外分享形式**(无访客账号) |
| FR-AUTH-08 | 审计日志 | M | 记录登录、文件增删改、权限变更、管理操作(见 FR-SYS-03) |

### 4.2 文件存储与多端访问/自动上传 — FR-FS
| 编号 | 需求 | 优先级 | 说明/验收要点 |
|---|---|---|---|
| FR-FS-01 | 目录浏览与文件管理 | M | 建目录、上传、下载、重命名、移动、复制、删除;Web 拖拽上传 |
| FR-FS-02 | 大文件可靠上传/下载 | M | 分块上传、断点续传、失败重试、校验和校验;下载支持 Range/流式 |
| FR-FS-03 | 回收站 | M | 删除进回收站,可恢复(含 UI 入口);默认保留期 30 天(管理员可配),到期清理 |
| FR-FS-04 | 版本历史与回滚 | M | **每次覆盖写入都生成新版本、绝不静默覆盖**(数据安全底线);版本浏览/回滚 UI 属 S 级增强,M2 先交付 API 与基础 UI |
| FR-FS-05 | 秒传/内容去重 | S | 相同内容只存一份(哈希判断),省空间、传得快 |
| FR-FS-06 | 多端访问与自动上传 | S | v1 范围:桌面设备自动上传(分块、断点续传、增量)+ 其他设备经 Web 访问/批量上传;镜像式文件夹同步客户端后置为独立阶段,冲突策略(保留双方/合并)届时单独立项设计 |
| FR-FS-07 | 搜索 | S | 按文件名搜索;**检索结果受 ACL 过滤**(只返回当前用户可见内容) |
| FR-FS-08 | 配额管理 | S | 每用户/共享空间可设容量上限;超限行为 = 拒绝写入 + 告警 |
| FR-FS-09 | 文件标签/星标 | C | 便于个人整理 |

### 4.3 照片与视频媒体管理 — FR-MEDIA
| 编号 | 需求 | 优先级 | 说明/验收要点 |
|---|---|---|---|
| FR-MEDIA-01 | 媒体自动入库与识别 | M | 识别常见图片/视频格式;读取 EXIF/拍摄时间 |
| FR-MEDIA-02 | 时间线浏览 | M | 按拍摄日期虚拟组织,缩略图瀑布流,月/日跳转(口径见 SC-3) |
| FR-MEDIA-03 | 缩略图生成 | M | 后台异步生成,懒加载;支持常见格式 |
| FR-MEDIA-04 | 图片预览/查看器 | M | 大图渐进加载、旋转、原图下载 |
| FR-MEDIA-05 | 智能相册/标签 | S | 按地点(EXIF GPS)、日期自动聚合;手动态/静图标签 |
| FR-MEDIA-06 | 视频在线播放 | S | **M3 先支持浏览器直放格式**;不兼容格式走转码(FR-STREAM-03,M5) |
| FR-MEDIA-07 | 照片上传与入库 | M | v1 通道:桌面 Agent **自动**上传所选相册/目录 + 手机/其他设备经 **Web 批量上传**(多选、可见进度);去重与增量适用于桌面通道(决策 D10) |
| FR-MEDIA-08 | 人脸识别/物体识别 | W | 依赖算力,后置单独评估(M7 候选) |

### 4.4 影音流媒体 — FR-STREAM
| 编号 | 需求 | 优先级 | 说明/验收要点 |
|---|---|---|---|
| FR-STREAM-01 | 媒体库与刮削 | S | 电影/剧集目录扫描,可插拔刮削源(数据源可配置、默认关闭,手动录入兜底) |
| FR-STREAM-02 | 海报墙浏览 | S | 按影片/剧集卡片展示,支持续播进度记忆 |
| FR-STREAM-03 | 转码服务 | S | 对浏览器不直接支持的格式转码(自适应码率 HLS/DASH);引擎抽象可插拔(ffmpeg);**M5 交付** |
| FR-STREAM-04 | Web 播放器 | M | 基于 HTML5/Media Source Extensions,移动端可用 |
| FR-STREAM-05 | 投屏(DLNA/Chromecast) | C | 后续版本 |
| FR-STREAM-06 | 字幕支持 | C | 内嵌/外挂字幕切换 |

### 4.5 集中备份 — FR-BACKUP
| 编号 | 需求 | 优先级 | 说明/验收要点 |
|---|---|---|---|
| FR-BACKUP-01 | 设备备份客户端(Agent) | M | 运行于 **macOS + Windows**(决策 D8;Linux 后置)的轻量客户端,按策略备份指定目录 |
| FR-BACKUP-02 | 增量备份与去重 | M | 只传变化块,断点续传,校验完整性 |
| FR-BACKUP-03 | 备份任务计划 | M | 定时/手动/实时(文件变化触发)三种模式 |
| FR-BACKUP-04 | 版本与轮换策略 | S | 保留多代版本,过期自动清理;支持按时间/数量策略 |
| FR-BACKUP-05 | NAS 自身数据出站备份 | S | NAS 数据备份到外接盘/另一台机器/对象存储(3-2-1 原则;默认每日,可配) |
| FR-BACKUP-06 | 恢复与演练 | M | 按文件/目录/整机恢复;文档化恢复流程,定期演练(见 SC-6) |
| FR-BACKUP-07 | 备份状态监控与告警 | M | 仪表盘展示每任务上次成功时间/失败(**站内告警**,M 不依赖邮件);邮件/Webhook 通道为 S(M5) |

### 4.6 系统与运维 — FR-SYS
| 编号 | 需求 | 优先级 | 说明/验收要点 |
|---|---|---|---|
| FR-SYS-01 | 后台任务队列 | M | 统一调度缩略图、转码、扫描、备份等耗时任务;可查看进度/重试 |
| FR-SYS-02 | 健康监控与告警 | S | 磁盘空间、CPU/内存、服务状态、任务失败率;低于阈值时通知(FR-SYS-04) |
| FR-SYS-03 | 审计日志(不可篡改) | M | 追加式日志:谁、何时、对什么、做了什么;管理员可检索 |
| FR-SYS-04 | 通知 | S | **站内通知先行**;邮件/Webhook 通道 M5 交付 |
| FR-SYS-05 | 统一配置与日志 | M | 配置文件/环境变量化;结构化日志,便于排障 |
| FR-SYS-06 | 数据完整性巡检 | S | 定期滚动校验数据哈希,发现静默损坏并告警 |

### 4.7 网络访问与安全 — FR-NET
| 编号 | 需求 | 优先级 | 说明/验收要点 |
|---|---|---|---|
| FR-NET-01 | 默认仅内网,全链路 TLS | M | 出厂不开外网;局域网内也走 HTTPS(自签/用户证书),杜绝明文口令 |
| FR-NET-02 | 可配置外网访问 | S | 提供"外网安全访问"方案与安全基线;**实现形态由 M1 架构 ADR-07 决定(独立 nginx 反代)** |
| FR-NET-03 | 叠加网(VPN)接入指引 | S | Tailscale/WireGuard 等一键接入指南,作为"偶尔外网访问"的推荐方案 |
| FR-NET-04 | 暴露面安全基线 | S | 外网开启时:登录限速、失败锁定、**开放注册默认关闭**、安全响应头 |
| FR-NET-05 | 端口与服务最小化 | M | 只暴露必要端口;内部服务不绑定 0.0.0.0 到公网 |

## 5. 非功能需求(NFR)

### 5.1 性能 NFR-PERF(基线在部署硬件落地后校准)
| 编号 | 指标 | 目标(可测口径) |
|---|---|---|
| NFR-PERF-01 | 局域网单流大文件吞吐 | **≥ 同一主机 iperf3 局域网基准的 80%**(部署时记录基线,验收对比;见 SC-4) |
| NFR-PERF-02 | 万级文件目录列表 | ≤ 500 ms |
| NFR-PERF-03 | 缩略图时间线(1000 张) | 首屏 ≤ 2 s(预热后),滚动懒加载不卡顿 |
| NFR-PERF-04 | 并发 | 支持 8 用户同时使用,无明显排队 |
| NFR-PERF-05 | 备份/自动上传增量扫描 | 10 万文件量级下,首次全量后每次增量扫描分钟级 |

### 5.2 安全 NFR-SEC
| 编号 | 要求 |
|---|---|
| NFR-SEC-01 | 传输层:TLS ≥ 1.2,禁用弱加密套件(系统内保证) |
| NFR-SEC-02 | 口令:强哈希(Argon2id/bcrypt),绝不明文存储 |
| NFR-SEC-03 | 授权:默认拒绝,最小权限;目录 ACL 处处校验(服务端,而非仅前端) |
| NFR-SEC-04 | 会话:Cookie HttpOnly/Secure/SameSite;CSRF 防护;上传做类型/大小/路径穿越校验 |
| NFR-SEC-05 | 审计日志只追加、不可被普通用户篡改 |
| NFR-SEC-06 | 依赖漏洞管理:最小化第三方依赖并定期更新(纯自研不等于零依赖) |
| NFR-SEC-07 | **at-rest 加密立场(决策 D11)**:数据静态加密由**部署层磁盘/卷加密**承担,系统内不实现应用层加密;系统仅负责传输加密与密钥/口令哈希的安全存储 |

### 5.3 可靠性与数据安全 NFR-REL
| 编号 | 要求 |
|---|---|
| NFR-REL-01 | 任何"写入"先落盘、可校验,再返回成功;断电/崩溃不留半截文件(幂等上传块) |
| NFR-REL-02 | 静默损坏可发现(内容哈希 + 定期巡检),发现即告警并可定位副本 |
| NFR-REL-03 | 数据物理布局与系统软件分离(数据目录独立,便于整体迁移/重装) |
| NFR-REL-04 | 备份遵循 3-2-1:NAS 上 1 份 + NAS 出站备份 1 份 + 不同介质/位置 1 份 |
| NFR-REL-05 | RPO 分两档口径:设备→NAS 上传 **尽力即时**(事件/定时触发,秒~分钟级);NAS 出站备份 **默认日级、可配**。RTO:整机恢复 ≤ 半天(含演练,见 SC-6) |

### 5.4 可移植性与部署 NFR-PORT
| 编号 | 要求 |
|---|---|
| NFR-PORT-01 | 纯软件、架构无关:可运行于主流 x86_64 / ARM64 Linux 环境 |
| NFR-PORT-02 | 交付形态:优先容器化(镜像 + compose),同时提供裸机运行说明 |
| NFR-PORT-03 | 无硬件绑定:不依赖特定磁盘控制器/RAID 卡;单盘可跑通全功能 |
| NFR-PORT-04 | 数据目录导出即迁移:把数据目录搬到新机器即可恢复(配合恢复文档) |

### 5.5 可维护性与可测试性 NFR-MAINT
- 模块化分层,核心逻辑与 UI 解耦;接口可单测(存储层、权限层、上传引擎为重点);
- 统一日志格式与级别;关键路径打点(耗时、错误率)便于定位;
- 新功能向后兼容;版本化 API;
- 需求可追踪:成功标准 ↔ FR/NFR 的映射见 §1.3;
- 文档随代码维护(架构/部署/恢复/开发四份手册)。

### 5.6 体验与界面 NFR-UX
- Web 为唯一端,响应式:桌面浏览器、平板、手机浏览器均可用;
- 中文优先,架构上支持 i18n(文案不硬编码);
- 大文件操作(上传/转码/备份)必须有可见进度与可取消性;
- 操作可逆优先:删除→回收站、覆盖→版本历史。

## 6. 优先级汇总(MoSCoW 一页)

| 级别 | 内容 |
|---|---|
| **Must(v1 核心)** | 多用户账号(仅管理员创建)与目录 ACL;文件浏览/上传/下载/删除/回收站;版本化写入(防覆盖丢数据);Web 端;照片入库+时间线+预览;照片上传(桌面自动 + Web 批量);设备目录自动备份+恢复;审计与 TLS;任务队列 |
| **Should(v1 完整)** | 分块断点续传、版本历史 UI、去重、配额;多端 Web 访问与自动上传;智能相册/标签;刮削海报墙+播放+转码(M5);增量备份与轮换;NAS 出站备份;外网访问+叠加网指引;健康监控与站内通知;邮件/Webhook 通知通道(M5);数据巡检 |
| **Could(后续,归 M7 及以后)** | 镜像同步客户端、只读外链、TOTP 两步验证、人脸识别、投屏、字幕、Linux Agent、内容级全文检索 |
| **Won't(v1)** | 下载器/PT、原生 App、移动后台自动上传、访客账号、分布式集群、插件生态、应用层 at-rest 加密、自研底层文件系统 |

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 从零自研范围过大,进度失控 | 项目夭折 | 严格按 MoSCoW 砍 W/C;里程碑独立交付;每个里程碑可独立使用 |
| 上传/版本/并发一致性难做对 | 数据丢失/错乱,信任崩塌 | 版本化写入为 M 底线(FR-FS-04);先写后元、幂等上传;镜像同步归 M7 先充分设计协议 |
| 手机照片仅手动上传,家人使用预期落差 | 家庭用户不愿用、数据回流失败 | Web 批量上传体验做顺(多选/进度/去重);M7 评估轻量移动通道;桌面自动通道覆盖主力设备 |
| 刮削/外网数据源不可用或不合规 | 功能不可用/法律风险 | 可插拔源设计、默认关闭;文档明确合规边界 |
| 单人维护负担重 | 文档与代码脱节 | 模块解耦、自动化测试、四份手册随代码维护;需求可追踪(§1.3) |
| 无硬件环境,性能目标不可验证 | 验收失真 | 用相对基线(SC-4)并在部署后校准;修订基线走配置管理 |

## 10. 术语表(节选)

| 术语 | 含义 |
|---|---|
| ACL | 访问控制列表,精确到目录级"谁能做什么" |
| MoSCoW | 需求优先级分级法(Must/Should/Could/Won't) |
| 3-2-1 备份 | 3 份副本、2 种介质、1 份异地 |
| RPO / RTO | 最多丢失多久的数据 / 多久恢复业务 |
| 刮削(Scraping) | 从元数据库抓取电影/剧集的海报、简介等 |
| Agent | 跑在桌面设备(macOS/Windows)上的自动上传/备份程序 |
| 叠加网(Overlay/VPN) | 在公网上建立加密私有网络(如 Tailscale/WireGuard) |
| at-rest 加密 | 数据在磁盘静止状态下的加密(本系统由部署层承担,见 D11) |
| 相对基线 | 在同一主机实测(如 iperf3)得到的性能参照,用于验收对比而非绝对值 |
